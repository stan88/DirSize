# 第 5 階段設計：前端（獨立視窗＋點選資料夾時的面板）

狀態：**第 7 節已決定**（2026-11-05）。第 8 節的實測完成後才實作。

## 1. 目標與範圍

- **獨立視窗程式**：瀏覽任一資料夾，看各子資料夾的大小。
- **點選資料夾時的面板**：在檔案總管裡點選一個資料夾時，旁邊的小面板列出**這個資料夾底下各子資料夾的大小**。這是使用者提出的需求，只參考「有這樣的功能」這個概念，外觀和實作都獨立設計。使用者確認的行為（2026-11-05）：
  - 面板固定貼在檔案總管視窗旁邊；
  - 點選別的資料夾就換內容；點選檔案、空白處就隱藏；
  - 不做「跟著目前資料夾」的面板，只由點選觸發。
- **檔案總管右鍵選單**：資料夾上的「用 DirSize 開啟」。
- **佈景主題跟著系統設定**：淺色、深色、高對比；系統切換時立刻跟著變。
- **輕量**：只用一般權限，透過服務查詢；不把任何程式碼載入檔案總管，所以前端出問題不會拖累檔案總管。
- 介面文字從一開始就和程式分開，第 6 階段再做多語系。
- 本階段**不做**：安裝程式、多語系翻譯（第 6 階段）。

## 2. 大小從哪裡來

- **資料夾**：問服務（`QueryFolder`），回應時間實測 0.4～6 ms。
- **檔案**（只有獨立視窗會用到）：直接列出資料夾內容。檔案名稱和大小本來就在列出結果裡，而服務的索引不存檔案名稱，所以不需要問服務。這是用使用者自己的權限列，看得到的範圍和檔案總管相同。
- **服務不能用的時候**：
  - 服務還在延遲啟動中（VM 實測：pipe 不存在，錯誤 2）：顯示「服務啟動中」，先逐目錄掃描；
  - 服務沒有安裝、磁碟不是 NTFS、外接磁碟：逐目錄掃描（第 1 階段的掃描程式），並顯示進度。
- **服務的狀態**：服務正在重掃時，標示「更新中」。沒有權限的子資料夾標示「沒有權限」，大小照樣顯示（8.1）。

## 3. 獨立視窗

- 上方是路徑列，左邊是資料夾樹，右邊是目前資料夾的內容清單：名稱、大小、磁碟用量、比例長條、檔案數。
- 預設依磁碟用量排序，可以點欄位標題改變排序。
- 雙擊資料夾就進入；右鍵選單有「在檔案總管開啟」「重新整理」。
- 清單由程式自己繪製（見第 5 節），比例長條也一起畫。

## 4. 點選資料夾時的面板

### 4.1 怎麼知道點選了哪個資料夾

- 用 `IShellWindows` 列出檔案總管視窗，再經過 `IShellBrowser::QueryActiveShellView` 取得目前顯示中的檢視（`IShellView`）。
- **讀取選取**：`IFolderView2::GetSelection`，有文件。只有「剛好選一個項目，而且是檔案系統上的資料夾」時才顯示面板；選檔案、選多個、什麼都沒選就隱藏。
  - 實測：什麼都沒選時，回傳 `HRESULT_FROM_WIN32(ERROR_NOT_FOUND)`，不是文件寫的 `S_FALSE`。程式把兩者都當成「選了 0 個」。
- **選取改變時的通知**：
  - 文件有寫：`IShellView::GetItemObject(SVGIO_BACKGROUND, IID_IDispatch)` 取得檢視的 ShellFolderView 物件；這個物件有 `SelectionChanged` 事件。
  - 文件只有 JScript 的寫法。C++ 要用 connection point 訂閱 `DShellFolderViewEvents`，這個 dispinterface 和 `DISPID_SELECTIONCHANGED` 只在 SDK 標頭檔裡（`shldisp.h`、`shdispid.h`）。開發機實測：跨行程訂閱成功，三個視窗都可以。
  - 備案：檔案總管在前景時，每 250 ms 讀一次選取。兩種做法的成本和反應時間都要實測（第 8 節）。
- **換資料夾、換分頁時**：舊的檢視會被換掉，訂閱也跟著失效。檔案總管在前景時，每 250 ms 檢查一次目前顯示中的檢視；換了就重新訂閱。這一步也要實測成本。
- **Windows 11 的分頁**：沒有官方文件。開發機實測（build 26300）：每個分頁是一個 `IShellWindows` 項目，`IShellBrowser` 的視窗類別是 `ShellTabWindowClass`。**所有分頁的檢視都回報看得見**，唯一的差別是 z-order：前面的分頁一定是這些 `IShellBrowser` 視窗中最上面的那個（3 次中 3 次）。所以：只有一個看得見的檢視就用它；不只一個就用 z-order 最上面的分頁；分頁視窗不在同一個父視窗下或找不到，就隱藏，不猜。這是依實測的行為，Windows 更新後可能要調整。
- **左邊的導覽窗格**：在那裡點資料夾是「切換目前資料夾」，不是在檢視裡選取，所以不會觸發面板。要實測確認。

### 4.2 怎麼跟著視窗

- 用 `SetWinEventHook`（`WINEVENT_OUTOFCONTEXT`）接收三類事件：
  - 前景視窗改變（`EVENT_SYSTEM_FOREGROUND`）；
  - 位置改變（`EVENT_OBJECT_LOCATIONCHANGE`）：只收檔案總管那個行程的事件，避免整個系統的游標、插入點事件一直喚醒程式；
  - 縮到最小與還原（`EVENT_SYSTEM_MINIMIZESTART`／`END`）。

  文件寫明，回呼會送到呼叫 `SetWinEventHook` 的那個執行緒，而且那個執行緒必須有訊息迴圈。
- 對齊時，用 `DWMWA_EXTENDED_FRAME_BOUNDS` 取得檔案總管實際看得到的外框，避開陰影的範圍。
- **貼在哪裡**（使用者確認）：右邊外側 → 放不下就左邊外側 → 再放不下就內側右邊；一定在螢幕的工作區域內。貼在內側時會和檔案總管重疊，要保持在檔案總管上面。
- **不設成檔案總管的 owned window**：文件寫明，owned window 一定在擁有者之上，擁有者縮到最小時會一起隱藏。但文件沒有說明擁有者在別的行程時會怎樣。VM 實測兩輪：面板停止回應時，**owned window 會讓檔案總管跟著卡住**，不設 owner 就不會。所以面板不設 owner，自己依 WinEvent 事件顯示、隱藏和移動。
- **跨行程的 COM 呼叫放到另一個執行緒**：VM 實測，讀選取偶爾要幾百 ms，不能讓面板跟著停住。
- 面板可以關閉、暫停，也可以設定「只在某些磁碟顯示」。

## 5. 佈景主題

- **淺色／深色**：用 `UISettings` 讀前景色判斷，並用 `ColorValuesChanged` 收到切換通知。這是 Microsoft 文件「在 Win32 app 套用 Windows 主題」的做法，需要 C++/WinRT 的標頭檔，Windows SDK 內就有，不用另外安裝。
- **標題列**：`DWMWA_USE_IMMERSIVE_DARK_MODE`。**文件寫明 Windows 11 build 22000 起才支援**，所以在 Windows 10 上標題列一律是淺色，只有內容會變深色。
- **高對比**：`SPI_GETHIGHCONTRAST` 的 `HCF_HIGHCONTRASTON`。文件要求：
  - 所有顏色改用一組前景色和背景色，用 `GetSysColor` 取得；
  - 不在文字後面放圖；
  - 啟動時和收到 `WM_SYSCOLORCHANGE` 時重新檢查。
- **內建控制項（ListView、TreeView）的深色模式沒有官方文件**，所以清單和樹狀結構由程式自己繪製，顏色才能完全依主題決定，不依賴沒有文件的做法。

## 6. 右鍵選單

- **傳統的登錄動詞**：只寫登錄機碼，不必載入任何程式碼到檔案總管。在 Windows 11 上會出現在「顯示更多選項」裡。文件說「顯示更多選項」只用來檢視舊式的擴充，所以這是依文件推論，要實測確認。
- **Windows 11 新的頂層右鍵選單**：要實作 `IExplorerCommand`，再用 sparse package 讓程式取得 app identity。文件寫明：
  - 安裝到使用者電腦上的 package，必須用目標電腦信任的憑證簽章；
  - 正式發行要用 IT 部門的憑證或 Azure Trusted Signing 這類服務；
  - 而且 `IExplorerCommand` 的程式碼會載入檔案總管執行。

  見 7.3。

## 7. 決定事項（2026-11-05 已決定）

- **7.1 技術：A**。Win32 原生 C++，和現有程式碼同一套。不需要執行階段，執行檔小、啟動快。清單自己繪製。（未採用：WinUI 3，要另外安裝 Windows App SDK 執行階段。）
- **7.2 Windows 11 分頁：A**。依實測結果實作；分辨不出看得見的檢視時，面板就隱藏，不猜。文件註明這是依實測的行為，Windows 更新後可能要調整。
- **7.3 右鍵選單：A**。先只做傳統的登錄動詞。Windows 11 上在「顯示更多選項」裡；不需要憑證，也不載入程式碼到檔案總管。（未採用：Windows 11 頂層選單，需要程式碼簽章憑證。）
- **7.4 面板的內容**：使用者後來說明，面板是**點選資料夾時**，列出被點選資料夾的**子資料夾**大小（見第 1 節），取代原本「跟著目前資料夾、列出資料夾和檔案」的構想。獨立視窗仍然列出資料夾和檔案。
- **7.5 面板的觸發與位置**（使用者確認）：固定貼在檔案總管旁。
  - **切換資料夾**時（左邊樹狀窗格、雙擊進入、上一頁），列出目前資料夾的子資料夾。使用者在 VM 測試時主要是在樹狀窗格點資料夾，確認這也要觸發。不是檔案系統資料夾的位置（例如「本機」）就隱藏。
  - **在清單選一個資料夾**，就改列出它的子資料夾；之後點檔案或空白處就隱藏。
  - 選了多個項目時也隱藏。這一點使用者沒有特別指定，是依「點檔案或空白處就隱藏」的同一個原則訂的預設，之後可以改。
  - 切換資料夾後，檔案總管有時會自動選取一個項目（例如按上一頁後選回原本的資料夾）。這不算使用者點選，所以面板仍然列出目前資料夾；之後選取再改變，才照清單的規則。這也是預設，之後可以改。
- **7.6 得知選取改變的方式**：VM（Windows 10）實測，`SelectionChanged` 事件幾乎不來，所以改成檔案總管在前景時每 250 ms 讀一次選取。目前的檢視會記住，只有它不見或被隱藏時、以及每 2 秒一次，才重新列出 `IShellWindows`。

## 8. 實作順序與驗證

1. **實測程式**（`tools/explorer_probe.cpp`，不出貨，一般權限；`scripts/explorer-probe-test.ps1` 依步驟執行，`scripts/package-explorer-probe.ps1` 打包給 VM）：
   - 列出檔案總管視窗，檢查能不能讀選取、能不能訂閱 `SelectionChanged`；
   - 面板跟著選取顯示和隱藏：用事件，和每 250 ms 讀一次，比較 CPU 和反應時間；
   - 換資料夾、換分頁之後，能不能找到新的檢視並重新訂閱；
   - 跨行程的 owned window 行為，以及面板停止回應時檔案總管會不會被拖住；
   - 傳統登錄動詞在 Windows 11 右鍵選單出現的位置。
2. 共用元件：主題（淺色、深色、高對比、切換通知）、自己繪製的清單、大小格式化，以及服務不能用時的逐目錄掃描。
3. 獨立視窗。
4. 點選資料夾時的面板。
5. 右鍵選單（登錄動詞，由獨立視窗的設定開啟和關閉；第 6 階段改由安裝程式處理）。
6. **驗證**：
   - 淺色、深色、高對比三種主題，以及即時切換；
   - 高 DPI 與多螢幕；
   - 服務啟動中、沒有安裝服務時的情況；
   - 檔案總管開很多視窗和分頁時，量測面板的 CPU 和記憶體用量。
