# 第 6 階段設計：安裝程式與多語系

狀態：**已定案**（2026-11-06）。第 7 節全部採用 A。

## 1. 目標與範圍

- **安裝程式**：一般使用者下載後，一個步驟就裝好 DirSize。
  - 取代目前的 `dirsize-service install|uninstall` CLI 指令（第 4 階段設計第 43 行）；
  - 安裝服務、複製程式、建立開始功能表捷徑、出現在「新增或移除程式」；
  - 註冊右鍵選單、設定開機自動啟動面板（第 5 階段排到這裡的兩項）；
  - 升級時保留索引快取；移除時清乾淨。
- **多語系**：介面文字已經全部集中在字串表（`src/app/dirsize.rc`），這個階段加上英文，並決定程式怎麼選語言。
- **版本與發行**：版本號、執行檔的版本資訊、GitHub Releases 的發行檔案。
- 本階段**不做**：自動更新、Windows 11 第一層右鍵選單（見 7.6，需要程式碼簽章憑證）。

## 2. 安裝程式技術

查證結果（連結見 DEVLOG「參考資料」，元件「第 6 階段設計」）：

| 方式 | 文件上的事實 | 優點 | 缺點 |
|---|---|---|---|
| **A. Inno Setup** | 授權：「Permission is granted to anyone to use this software for any purpose, including commercial applications」，條件是保留著作權聲明、修改版要標示。沒有說會限制產出的安裝程式。 | 授權寬鬆，開源專案可以自由使用；產出一個 setup.exe；「新增或移除程式」的項目、移除程式、升級都由它處理 | 第三方工具（Pascal 腳本），要裝在建置機上；服務的安裝由我們的 `dirsize-service install` 處理 |
| **B. MSI（用 WiX 建置）** | Windows Installer 的 ServiceInstall／ServiceControl 表可以安裝、停止、刪除服務；MsiServiceConfig 表可以設延遲啟動（Windows Installer 5.0 起）；major upgrade 用 UpgradeCode 和 RemoveExistingProducts。WiX 的授權是 **MS-RL**；README 寫「use of the WiX Toolset requires an Open Source Maintenance Fee」，EULA 第 1 節卻寫只適用於年營收 1 萬美元以上的營利使用。 | 系統標準格式；服務、升級、移除都由 Windows Installer 處理；企業可以用群組原則部署 | WiX 的維護費條款，README 和 EULA 說法不一致；建置要裝 .NET SDK 和 WiX |
| **C. 自己寫 setup.exe（C++）** | 「新增或移除程式」讀的 Uninstall 登錄機碼，文件只列出 Windows Installer 會寫的值，**沒有說明不用 MSI 時要寫哪些值**。 | 不依賴任何第三方工具；和現有程式碼同一套 | 移除程式要刪除自己、升級時要處理檔案被鎖住，這些都得自己做；Uninstall 機碼的寫法沒有文件依據 |

- **建議 A**。授權沒有疑慮，產出的檔案最單純，常見的安裝問題都有現成處理。服務本身的安裝邏輯已經寫好並在 VM 上驗證過（第 4 階段），安裝程式只要呼叫它。
- 不管選哪一種，**安裝都需要系統管理員權限**，因為要安裝服務、寫入 Program Files。

## 3. 安裝內容

- **程式檔**：`C:\Program Files\DirSize\` 下的 `dirsize.exe`、`dirsize-service.exe`、`dirsize-cli.exe`，再加上授權檔。
  - 目前 `dirsize-service install` 會把自己複製到 Program Files；改由安裝程式負責複製以後，服務只要註冊就好。
  - 這個資料夾一般使用者不能寫入，所以服務的執行檔不會被替換（第 4 階段的要求）。
- **服務**：自動啟動、延遲啟動、LocalSystem，和第 4 階段相同。
- **開始功能表**：一個「DirSize」捷徑，開啟獨立視窗。
- **右鍵選單和面板自動啟動**：見 7.2。
- **快取**：`C:\ProgramData\DirSize\`，由服務建立。升級時保留；移除時是否刪除，見 7.4。

## 4. 升級與移除

- **升級**：停止服務 → 換掉檔案 → 啟動服務。
  - 快取的格式如果改了，現有的驗證會拒絕舊快取，服務就重建索引（第 3 階段第 4 步）。這是現有的行為，不需要另外處理。
  - 面板如果正在執行，要先關掉，否則檔案被鎖住、換不掉。關掉的方式，在實作時依選定的工具確認。
- **移除**：停止並刪除服務 → 刪除程式檔、捷徑、登錄項目 →（依 7.4）刪除快取。

## 5. 多語系

- **語言**：繁體中文（現有）＋英文。
- **選語言的方式**（查證結果）：
  - 一個執行檔裡放好幾種 `LANGUAGE` 的字串表時，`LoadString` 會選哪一種，**LoadString 頁和 STRINGTABLE 頁都沒有寫**。FindResourceExW 的頁面連不上（404）。
  - UI 語言管理的頁面寫了 MUI 檔案的語言選擇順序：執行緒偏好 → 行程偏好 → 使用者 UI 語言 → 系統 UI 語言 → 系統預設，但那是針對 `.mui` 語言檔寫的。
  - `SetThreadPreferredUILanguages` 的頁面寫明：設定之後，執行緒的偏好會優先於使用者的偏好，「Resource-loading functions, such as LoadString ... make calls to GetThreadPreferredUILanguages」。
  - 所以有兩條路，見 7.5。
- **預設**：跟著 Windows 的顯示語言。設定裡可以手動切換（「⋯」選單）。
  - 實測（DEVLOG 2026-11-06）：中性語言（en、zh-Hant）對不到有地區的字串表，例如 zh-HK 會拿到英文。所以程式自己選：依序看使用者的偏好清單，繁體中文（zh-TW、zh-HK、zh-MO、zh-Hant）用 zh-TW，英文（en-*）用 en-US，其他（包括簡體中文 zh-CN、zh-SG）跳過；都沒有就用 en-US。
  - 選好後用 `SetProcessPreferredUILanguages` 設定，背景執行緒也會照這個語言。
  - 每種語言都要有全部字串（缺的字串不會改用另一種語言），用測試檢查。
- **語系檔**（使用者決定，2026-11-06）：開源專案要方便別人貢獻翻譯，所以字串不再直接寫在 `.rc`，改成 `lang/<語言>.json`，每種語言一個檔案。
  - 建置時由 `cmake/gen_lang.cmake`（CMake 的 `string(JSON)`，3.19 起）轉成字串表，編進 exe：**仍然是一個 exe**，7.5 A 不變。
  - 每個檔案寫明 `locale`、`winnt.h` 的 `LANG_`／`SUBLANG_` 名稱，以及 `matches`（這個檔案適用哪些 Windows 顯示語言）。上面的對應規則就由 `matches` 決定：zh-TW 檔寫 `zh-TW、zh-HK、zh-MO、zh-Hant`，en-US 檔寫 `en`。新增語言不用改程式。
  - en-US 是基準，缺 ID 就建置失敗；其他語言缺的字串用英文補，並發出警告；`%1` 這類占位符號和英文不同就建置失敗。
  - 原本用串接的字串（「合計 」＋數字、數字＋「 個檔案」、「錯誤碼 」＋數字）改成 `%1`，讓翻譯可以調整語序。
  - 給翻譯者的說明：`lang/README.md`。
  - 安裝程式（Inno Setup）有自己的訊息檔，它的字串不在這個流程裡，做安裝程式時另外處理。
  - 右鍵選單的文字（`IDS_VERB_TEXT`）目前是寫入登錄的當下用的語言。7.2 A 由安裝程式寫進 HKLM、給所有使用者，就只會有一種語言。做安裝程式前，先查文件：傳統動詞能不能指向 exe 裡的字串資源，讓每個使用者看到自己的語言。
- **範圍**：只翻譯介面（`dirsize.exe` 和安裝程式）。服務的記錄檔和 CLI 輸出維持英文，因為這些是給排查問題用的，不是給一般使用者看的。

## 6. 版本、簽章、發行

- **版本號**：`0.1.0` 起，三段式（主.次.修補）。每個執行檔都加上 `VERSIONINFO` 資源，「內容」頁就看得到版本。
- **程式碼簽章**：見 7.3。
  - SmartScreen 文件：沒有信譽的下載檔案會顯示警告；
  - UAC 文件：沒有簽章的程式要求提升權限時，提示框是黃色背景（「the application is unsigned or signed but isn't trusted」）。
- **發行**：GitHub Releases 放 setup.exe，加上一份不用安裝的 zip（給只想用獨立視窗的人）。
- README 的狀態要更新，目前寫的是「還沒有可用的版本」。

## 7. 決定事項

使用者決定：7.1～7.6 全部採用 A（2026-11-06）。

- **7.1 安裝程式技術**：A Inno Setup（建議）／B MSI（WiX）／C 自己寫。見第 2 節。
- **7.2 右鍵選單和面板自動啟動由誰設定**：
  - **A（建議）**：
    - **右鍵選單**：安裝程式的選項，預設勾選，寫在 HKLM（所有使用者）。移除時一定刪得乾淨。程式裡「⋯」的開關，偵測到安裝程式已經設定時，就顯示成「由安裝程式設定」，不能在程式裡切換。
    - **面板自動啟動**：程式裡「⋯」新增「登入時自動啟動面板」，寫在 HKCU 的 Run（每個使用者自己決定）。
    - 安裝程式最後一頁可以勾選「現在啟動面板」。
  - B：全部都在程式裡用 HKCU 設定，安裝程式不管。缺點：移除後，其他使用者的 HKCU 裡會留下指向已刪除程式的項目；安裝程式只清得到執行它的那個帳號。
  - C：全部由安裝程式寫在 HKLM。缺點：面板會對所有使用者自動啟動，個人不能選。
  - 備註：「一般使用者用管理員帳密提升權限時，安裝程式的 HKCU 會是管理員的」，這次找到的文件沒有寫明。所以 A 讓 HKCU 的設定由程式本身用一般權限寫入，不由提升權限後的安裝程式寫。
- **7.3 程式碼簽章**：
  - **A（建議）**：先不簽章，使用者會看到 SmartScreen 警告和黃色的 UAC 提示，README 說明原因；
  - B：申請 Azure Trusted Signing 或購買憑證（有費用，需要身分驗證）。
- **7.4 移除時的快取**：
  - **A（建議）**：一起刪除，`ProgramData\DirSize` 整個資料夾，包括記錄檔；
  - B：保留，重新安裝時就不用重建索引；
  - C：讓使用者勾選。
- **7.5 多語系的做法**：
  - **A（建議）**：字串表都放在同一個 exe，程式啟動時自己決定語言，再用 `SetThreadPreferredUILanguages` 指定。哪個字串表會被選中，文件沒有寫明，所以**先寫一個實測程式確認**，沒問題才採用。
    - 實測後改用 `SetProcessPreferredUILanguages`（執行緒的設定不會傳給新執行緒）；字串來源改成 `lang/*.json`，見第 5 節。
  - B：MUI 語言檔（`dirsize.exe.mui` 放在語言名稱的子資料夾）。這是文件建議的做法，但建置和安裝都比較複雜。
- **7.6 Windows 11 第一層右鍵選單**：
  - **A（建議）**：這個階段不做，維持「顯示更多選項」；
  - B：如果 7.3 選了 B，可以另外做 `IExplorerCommand` 加 sparse package。

## 8. 實作順序與驗證

1. **實測程式**：多語系字串表的選擇（7.5 A），在中文和英文的 Windows 上各測一次，也測手動切換語言。
2. 版本資源、英文字串表、語言切換。
3. 安裝程式腳本和建置腳本（輸出到 `dist\`，不進 git）。
4. 程式裡的「登入時自動啟動面板」，以及「由安裝程式設定」的顯示（7.2 A）。
5. **驗證（VM）**：
   - 全新安裝：服務執行中、開始功能表捷徑、「新增或移除程式」的項目、右鍵選單；
   - 用一般使用者帳號加上管理員帳密安裝，確認面板自動啟動和右鍵選單設在正確的帳號；
   - 升級：裝舊版 → 裝新版，快取保留，服務重新啟動；
   - 面板執行中時升級；
   - 移除：服務、檔案、登錄、（依 7.4）快取都清乾淨；
   - 中文和英文的 Windows 各看一次介面。
